# AI Agent Platform (MVP, Phase 0-2)

Chat app (Flutter) + always-on backend (FastAPI on Render) + Gemini agent that controls
Kaggle and Hugging Face through tools. First use-case: **host a model** (Hugging Face Space).

```
Flutter app --HTTPS--> Render web service (FastAPI + agent worker thread + Postgres)
                          |-- Gemini API (function calling)
                          |-- Kaggle CLI (run scripts)
                          '-- Hugging Face Hub (models, Spaces)
```

## 1. Deploy backend on Render

1. Push this folder to a GitHub repo (the `render.yaml` is at the root, code in `backend/`).
2. Render dashboard -> **New Postgres** (paid; free Postgres expires after 30 days). Copy its **Internal Database URL**.
3. Render -> **New > Blueprint** -> pick the repo. The web service uses a **paid plan** on purpose
   (free services sleep after 15 min idle and would stop the agent).
4. Fill the environment variables (Render keeps them secret):

| Variable | Where to get it |
|---|---|
| `APP_TOKEN` | auto-generated by the blueprint; copy it into the app |
| `DATABASE_URL` | Postgres Internal Database URL |
| `GEMINI_API_KEY` | Google AI Studio |
| `KAGGLE_USERNAME`, `KAGGLE_API_TOKEN` | kaggle.com -> Settings -> API (new token `KGAT_...`). Legacy: use `KAGGLE_KEY` instead of the token |
| `HF_TOKEN` | huggingface.co -> Settings -> Access Tokens -> **write** |

5. Check `https://<your-service>.onrender.com/health` returns `{"ok": true}`.
6. Kaggle: verify your phone number on kaggle.com (needed for internet and GPU in notebooks).

Keep **one** uvicorn process (the scheduler runs inside it). Do not add `--workers`.

## 2. Build the mobile app

```bash
flutter create --project-name agent_app app_shell
cp -r mobile/lib app_shell/ && cp mobile/pubspec.yaml app_shell/pubspec.yaml
cd app_shell && flutter pub get && flutter run
```
Android release builds: add `<uses-permission android:name="android.permission.INTERNET"/>` to
`android/app/src/main/AndroidManifest.xml`. On first start enter the Render URL and `APP_TOKEN`.
**Never put Kaggle/HF/Gemini keys in the app.**

## 4. How the plan's ideas map to code

| Plan | Code |
|---|---|
| Agent loop + checkpoints | `app/agent.py` (every step stored in `events`; restart resumes) |
| Run without the app open | `app/worker.py` (queue, sleeping tasks, watchers) |
| 5-layer memory | conversation = `events`, task state = `tasks`, long-term/skills/lessons = `memory` table |
| Skills + self-learning | `memory_tool.py` (lessons need evidence, skills stay *draft* until you approve in the app), reflection after tasks with errors |
| Permission tiers | `tools/__init__.py: approval_reason` (GPU, public repos, token-in-Space need approval) |
| Kill switch, pause, stop | app menu -> `/control/kill`, `/control/pause`, per-chat stop |
| Secrets never reach the LLM | keys only in env; `textutil.redact` scrubs every tool result and log |
| Prompt-injection guard | tool output is data; system prompt says never obey it; tools are allow-listed and validated |

## 5. Honest limits (read this)

- **Not run end to end.** This environment had no internet. Tested: unit tests for the pure logic
  (`cd backend && python -m unittest discover -s tests`, 11 pass) and syntax checks of all Python.
  The FastAPI app, Gemini/Kaggle/Hugging Face calls and the Flutter app were **not executed**. Expect a few
  small fixes on first run; send me the error text and I will fix it.
- **Gemini model name:** default list in `GEMINI_MODELS` tries newest first and falls back on "not found". Check Google's model page.
- **Kaggle CLI output format** can change between versions; status parsing is in `app/kaggle_parse.py`.
- **Render disk is ephemeral and small.** Models downloaded from Kaggle outputs and re-uploaded to Hugging Face must fit on it.
  For big models, hosting an existing Hub model (Path A) is the reliable route.
- **Free HF Spaces (CPU)** only run small models. The agent never requests paid hardware.
- GPU hours are tracked by the agent as a safety cap; Kaggle's real quota is only visible on kaggle.com.
- Not in the MVP: push notifications (Firebase), vector search (pgvector), other providers (Modal/Colab), database migrations.
  The app polls every 3 s; notifications are Phase 2.
- Check Kaggle's Terms before heavy automation; keep GPU use modest.
